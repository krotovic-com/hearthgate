Hearthgate is the single gateway between the internet and your home server. Publish the services you choose with automatic certificates. Reach the rest over the built-in WireGuard VPN.

Secure by default

Closed until you open it.

A fresh install exposes nothing to the internet. Each public port exists because a public interface asked for it, and every other port is dropped by the firewall. Hearthgate can always tell you why.

  • Ports nobody publishes stay closed, including ones that Docker published with -p.
  • Internal services stay reachable over the VPN at name.home.internal.
  • The dashboard only answers on your LAN and the VPN. It never gets a public port.
  • A firewall change that locks you out undoes itself after 60 seconds.

What's in 1.0

The reverse proxy, firewall, VPN and container manager, in one service.

Hearthgate replaces the usual stack of a proxy, a certificate tool, firewall scripts, a VPN server and a container UI. They share one configuration, so they can't disagree about what is open.

Expose

Publish exactly what you choose, with TLS handled.

Public interfaces

A domain plus public ports, TCP, UDP or both. Certificates from Let's Encrypt or any ACME CA are issued and renewed automatically, wildcards included through DNS-01.

cloud.example.com · 443/tcp · https

Routes and load balancing

Send a port to one or more services by host and path. Round-robin with weights, least connections or source hash, with active health checks.

web:443 → app-1, app-2 ×2

TLS your way

Terminate TLS in Hearthgate, or pass it through untouched by server name on the same port. Upload your own certificates if you prefer.

Router port forwarding

Optionally keeps your router's forwards in line with your public interfaces over UPnP or NAT-PMP, and warns you about double NAT.

Protect

Everything else stays shut, and you can see why.

Firewall and blocklists

An nftables firewall that closes every port no interface opens. Add your own rules, subscribe to blocklists, block countries and set rate limits per interface.

Automatic bans

Clients that probe closed ports or fail to log in collect points and get banned for a while. You set the threshold, window and ban time.

20 points in 10m → ban 1h

Reach

Get to every service from anywhere, without publishing it.

Built-in WireGuard VPN

Add a phone or laptop by scanning a QR code. Each peer reaches every internal service, or only the few you allow.

Internal DNS

Services resolve by name over the VPN, so you type nas.home.internal instead of remembering addresses.

ssh.home.internal → 10.0.0.5

Run

Manage the house from one place.

Managed Docker

Run containers and Compose stacks from Hearthgate, update them on request and read their logs. Routes reach them without publishing a single host port.

Web dashboard

Live health and traffic, two-factor login and API tokens. It answers only on your LAN and the VPN.

Revisions and rollback

Every change is a numbered revision with a diff. Changes apply within a second, without dropping open connections, and roll back just as fast.

CLI, API and metrics

A REST API with an OpenAPI document, a CLI for scripts, and Prometheus metrics. Notifications and backups are built in.

AI assistant coming next

Bring your own provider, such as Claude, Gemini, OpenAI or Ollama, to review rules and troubleshoot services. Suggestions wait for your approval, and logs are redacted before they leave the machine.

Notifications

Hear about certificate renewals, failing health checks, bans, backups and updates by email or webhook.

Dashboard

See what's open, what's healthy and who's knocking.

Edits go into a draft. You review the diff, then apply it as a new revision.

Or describe it in a file

Your whole gateway in one TOML file.

Validate it, apply it, and get a revision you can diff and roll back. The dashboard and the file are two views of the same state.

state.tomlexcerpt
[[interfaces]]
name = "web"
domains = ["app.example.com"]
listeners = [
  { port = 80,  mode = "http" },
  { port = 443, mode = "https" },
]

[[services]]
name = "app-1"
kind = "external"
host = "10.0.0.11"
ports = { http = 8080 }
health = { type = "http", path = "/healthz" }

[[routes]]
name = "app"
interface = "web"
listener = 443
strategy = "round-robin"
targets = [
  { service = "app-1", port = "http" },
  { service = "app-2", port = "http", weight = 2 },
]

Install Hearthgate 1.0.0

Runs on Debian, Ubuntu, Fedora, RHEL, openSUSE and any other Linux with systemd. The binaries are static, so the archive works on any distribution.

  1. Install with the script or a package for your system.
  2. Print the setup code with sudo -u hearthgate hearthgate setup-code.
  3. Open https://SERVER-LAN-ADDRESS:7380/ from your network and create the admin account.

Prefer to build it yourself? Build from source with cargo build --release.
